Event Loop — Cơ chế hoạt động

Node.js dùng một luồng JavaScript duy nhất + event loop. I/O thật chạy ở Worker Pool (C++, đa thread). Khi I/O xong → callback vào poll queue → event loop lấy lên Call Stack.

Mấu chốt: Mỗi callback chạy atomic (không bị gián đoạn). Nhưng thứ tự giữa các callback là không xác định — nguồn gốc mọi concurrency bug.

Cái bẫy await — async/await KHÔNG giải quyết race

Lầm tưởng phổ biến: "Dùng async/await là code chạy tuần tự, không có race."
Sai. Mỗi await là một điểm nhường CPU — callback khác có thể chen vào giữa các await.

❌ Bug — 2 request chạy đồng thời
async function handler(req) {
    // ← await #1: nhường CPU, request B chen vào đây!
    const data = await db.find(req.id);

    // Lúc này data đã stale — B đã đọc cùng giá trị
    // ← await #2: nhường CPU lần nữa
    await db.update(req.id, data + 1);
    // B cũng update cùng giá trị → mất 1 update!
}

Thêm flag/guard để skip nếu đã có callback khác đang xử lý cùng item. Phổ biến nhất — 26% bug được sửa theo cách này.
❌ Lỗi — 2 callback cùng xử lý job
// Không có guard
queue.on('job', async (job) => {
    await processJob(job);
    await markDone(job.id);
    // Nếu 2 event cùng job →
    // processJob chạy 2 lần!
});
✓ Sửa — Set-based bypass guard
const processing = new Set();

queue.on('job', async (job) => {
    if (processing.has(job.id)) return;
    processing.add(job.id);   // lock
    try {
        await processJob(job);
        await markDone(job.id);
    } finally {
        processing.delete(job.id); // unlock
    }
});
Đảm bảo thứ tự bằng callback lồng nhau, Promise chain, hoặc async/await. Dùng cho Order Violation.
❌ Lỗi — upload trước khi create xong
var bundle = client.bundle('test');

// create() async — return ngay!
bundle.create({name: 'test'}, callback);

// Chạy ngay — create chưa xong!
bundle.uploadStr('content', cb);
// Error: bundle does not exist
✓ Sửa — nested callback / await
var bundle = client.bundle('test');

// Async/await — đảm bảo thứ tự
await bundle.create({name: 'test'});
// Chắc chắn create xong rồi mới upload
await bundle.uploadStr('content');
// ✓ Không còn race
Thay 3 bước read-modify-write bằng 1 thao tác atomic ở DB/Redis. DB đảm bảo không có race condition.
❌ Lỗi — 3 bước riêng lẻ có race
async function addToList(userId, item) {
    // BƯỚC 1: đọc
    const user = await User.findById(userId);
    // BƯỚC 2: sửa (2 request đọc cùng state)
    user.items.push(item);
    // BƯỚC 3: ghi (ghi đè lẫn nhau!)
    await user.save();
}
✓ Sửa — MongoDB $push atomic
async function addToList(userId, item) {
    // 1 thao tác duy nhất — atomic
    await User.updateOne(
        { _id: userId },
        { $push: { items: item } }
    );
    // DB đảm bảo không có race
    // Không cần read trước!
}
Cho phép lỗi xảy ra, bắt exception và phục hồi. Dùng khi race condition xảy ra ít và có thể handle được.
❌ Lỗi — crash khi duplicate
async function insertUser(email) {
    // 2 request đồng thời →
    // 2 cái cùng insert → DUPLICATE KEY!
    return await db.insert({ email });
    // Crash nếu duplicate!
}
✓ Sửa — catch và phục hồi
async function insertUser(email) {
    try {
        return await db.insert({ email });
    } catch (err) {
        if (err.code === 'DUPLICATE_KEY') {
            // Tolerance: dùng record đã tồn tại
            return await db.findOne({ email });
        }
        throw err;
    }
}
Biến shared variable → local variable trong callback. Mỗi callback có bản sao riêng → không race. ⚠️ Cảnh báo: có thể tạo ra shared variable mới khác!
❌ Lỗi — shared variable
// SHARED — tất cả requests dùng chung!
let currentUser = null;

router.get('/profile', async (req, res) => {
    currentUser = await User.findById(
        req.userId
    );
    // Request B ghi đè currentUser
    // của Request A!
    res.json(currentUser);
});
✓ Sửa — local variable
// Không còn shared variable ngoài!

router.get('/profile', async (req, res) => {
    // LOCAL — riêng mỗi request
    const user = await User.findById(
        req.userId
    );
    // Mỗi request có user riêng
    // Không thể race!
    res.json(user);
});
Đổi setImmediate ↔ process.nextTick để thay đổi thứ tự ưu tiên. Dùng cho Starvation bugs.
❌ Lỗi — hapi#3347: setImmediate bị starve
// setImmediate priority THẤP
// Dưới tải I/O nặng → không bao giờ chạy!
function processNotification(item) {
    setImmediate(() => item.callback());
    setImmediate(() => internals.emit(item));
    // Queue tăng không giới hạn → OOM!
}
✓ Sửa — process.nextTick priority cao
// nextTick priority CAO NHẤT
// Chạy trước cả I/O callbacks
function processNotification(item) {
    process.nextTick(itemCallback, item);
    process.nextTick(emitEmitter, item);
    // Chắc chắn chạy sớm, queue không tích lũy
}
